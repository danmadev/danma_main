Проверены установка Python-пакета, сборка Rust-нод и совместимость с PyTorch 2.8 CPU. [Результат GitHub Actions](https://github.com/stanta/neuromorph/actions/runs/36181672828).

После запуска нод адаптер используется как обычный модуль PyTorch:

```python id="0r2eh4"
import torch
from danma_torch import DANMAClient, DANMALinear

client = DANMAClient("127.0.0.1", 9101)
layer = DANMALinear(
    client,
    neuron_ids=(11, 21, 31),
    input_ids=(901, 902),
)

x = torch.tensor([1.0, 2.0])
loss = layer(x).square().sum()
loss.backward()  # Обучение удалённых нейронов DANMA
```

Команды запуска трёх нод и настройки их весов находятся в [инструкции `danma-torch`](https://github.com/danmadev/danma_main/blob/main/python/README.md).

Следующая граница разработки — нативное устройство `danma:0`. Для него потребуется отдельный `PrivateUse1` backend с регистрацией операций и управлением памятью; нынешний адаптер уже позволяет обучать DANMA из PyTorch, но не подменяет его систему устройств.

## Новая граница разработки: нейрон по запросу

Перед полноценным `danma:0` в Runtime добавляется demand-driven жизненный цикл нейронов:

1. На старте физически создаётся только входной фронт нейронов.
2. Остальные нейроны существуют как `VirtualNeuronID` и потенциальные связи со случайными начальными весами/seed без полного объекта в RAM.
3. Нейрон материализуется идемпотентно при фактическом достижении его обратным обучающим сигналом.
4. Для связей ведутся `usage_count` / `update_count` / gradient statistics, чтобы отличать реально участвовавшие связи от неиспользованных.
5. После закрытия feedback TTL/checkpoint выполняется pruning: неиспользованные потенциальные связи схлопываются, а рабочий активный подграф сохраняется.
6. Тестовая цель: при ~1000 потенциальных дендритах и ~1000 потенциальных аксонах на логический нейрон фактически хранить только реально востребованные десятки связей, если обучение их не активировало.

Это становится частью CPU Runtime и распределённого этапа до нативного `PrivateUse1`: сначала доказать корректность lazy materialization + pruning и измерить фактическую экономию памяти, затем переносить этот Runtime под `danma:0`.
